# EKS demo cluster

This directory creates an Amazon EKS cluster with the same Kubernetes resources as `k8s-local-cluster-tool`.

The default configuration uses `us-east-1`, two `t3.medium` managed nodes, and the AWS EBS CSI add-on for the demo PVC. EKS and EC2 resources incur AWS charges while they exist.

## Prerequisites

Install and authenticate these tools:

```sh
aws --version
kubectl version --client
eksctl version
aws sts get-caller-identity
```

If `eksctl` is not installed on WSL2 Linux AMD64, install the latest release:

```sh
cd /tmp
curl --fail --location --remote-name https://github.com/eksctl-io/eksctl/releases/latest/download/eksctl_Linux_amd64.tar.gz
tar -xzf eksctl_Linux_amd64.tar.gz
sudo install -m 0755 eksctl /usr/local/bin/eksctl
eksctl version
```

The AWS identity that creates the cluster receives initial administrative access. For the repository's EKS MVP, the default AWS CLI profile can be used:

```sh
aws sso login --profile default
```

If your AWS profile is not `default`, replace `--profile default` in the commands below.

## Daily lifecycle script

The recommended workflow is to use `cluster.sh` from this directory:

```sh
chmod +x cluster.sh
./cluster.sh create
```

The `create` command validates AWS access, creates the cluster when it does not exist, updates kubeconfig, applies the demo resources, and waits for the API deployment.

Check the environment:

```sh
./cluster.sh status
```

At the end of the day, delete the demo resources and the EKS infrastructure:

```sh
./cluster.sh destroy
```

The destroy command asks you to type the cluster name. For an unattended cleanup, use:

```sh
./cluster.sh destroy --yes
```

The script defaults to the `default` AWS profile and `us-east-1`. Override either value when needed:

```sh
./cluster.sh create --profile company-dev --region eu-west-1
```

## Create the cluster

Run these commands from this directory:

```sh
aws eks list-clusters --profile default --region us-east-1
eksctl create cluster -f eks-cluster.yaml --profile default
aws eks update-kubeconfig --name cluster-to-be-monitorized --region us-east-1 --profile default
kubectl cluster-info
kubectl get nodes
```

The `eksctl` configuration installs the managed node group and the EBS CSI add-on required by the PersistentVolumeClaim.

If cluster creation reports that `aws-ebs-csi-driver` is still `CREATING` or times out, the cluster and nodes may already be healthy. Check the add-on before retrying:

```sh
aws eks describe-addon \
	--cluster-name cluster-to-be-monitorized \
	--addon-name aws-ebs-csi-driver \
	--region us-east-1 \
	--profile default
```

The configuration enables the cluster OIDC provider so `eksctl` can attach the required IAM permissions to the EBS CSI controller. For an existing cluster created before this setting was added, associate OIDC and retry the add-on update:

```sh
eksctl utils associate-iam-oidc-provider \
	--cluster cluster-to-be-monitorized \
	--region us-east-1 \
	--approve \
	--profile default

eksctl update addon \
	--config-file eks-cluster.yaml \
	--name aws-ebs-csi-driver \
	--cluster cluster-to-be-monitorized \
	--region us-east-1 \
	--profile default \
	--force
```

Then verify that the add-on is active:

```sh
aws eks describe-addon \
	--cluster-name cluster-to-be-monitorized \
	--addon-name aws-ebs-csi-driver \
	--region us-east-1 \
	--profile default \
	--query 'addon.status' \
	--output text
```

## Deploy the demo resources

```sh
kubectl apply -f cluster-resources.yaml
kubectl get all -n monitoring-demo
kubectl get pvc -n monitoring-demo
kubectl get jobs,cronjobs -n monitoring-demo
```

The deployment includes a Namespace, ConfigMap, Secret, Deployment, Services, StatefulSet, DaemonSet, Job, CronJob, PersistentVolumeClaim, ResourceQuota, and LimitRange.

The Secret contains demo credentials only. Do not use these values in a real environment.

## Connect KubeBudget

Use the KubeBudget cluster connection dialog with:

- Connection source: `Amazon EKS`
- Cluster name: `cluster-to-be-monitorized`
- AWS region: `us-east-1`
- AWS profile: `default` or leave it empty to use the default profile

The dashboard uses the kubeconfig context generated by `aws eks update-kubeconfig`.

## Cleanup

Delete the demo workloads first if you want to remove them separately:

```sh
kubectl delete -f cluster-resources.yaml
```

Delete the EKS cluster and its managed resources when finished:

```sh
eksctl delete cluster -f eks-cluster.yaml --profile default
```

Confirm deletion before leaving the AWS account to avoid ongoing charges.
